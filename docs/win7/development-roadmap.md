# Win7 实测后的开发计划

2026-11-24 · 对应实施台账 W01–W06。目标仍为 Win7 SP1 x64 上的本地桌面应用和非 PDF Office 工作流，验收以仓库现有标准为准。[实施方案](../../GenOffice_Win7_Implementation_Plan.md) · [验收矩阵](acceptance.md)

## 先验证运行时

Win7 客体能启动系统自带的 `cmd.exe`，原版 Electron 43.8.10 返回 Win32 错误 193。仅在诊断副本上将 PE 的 OS 与子系统版本从 10.0 改为 6.1 后，Windows 创建了进程，随后以 `0xC0000139` 退出。对客体的导出检查确认 Electron 导入的多项 API 缺失，其中包括进程缓解策略接口。两次结果分别暴露了进程创建和导入解析的阻断，RT02–RT09 仍然受阻。[Win7 实测](evidence/docker-win7-stock.json) · [Electron Win7 支持公告](https://www.electronjs.org/blog/windows-7-to-8-1-deprecation-notice)

兼容层首轮优先测试适用版本能否覆盖原版 Electron 的启动方式。CopperFr 的 1.1.3.1455 已移除专门处理该 Win32 错误的选项，应在候选评估时核对实际支持的启动路径和配置范围。该版本的发布说明及其他 Electron 应用记录仅作为候选筛选依据。按项目约束，兼容配置需要保持在待测程序范围内。[CopperFr 发布说明](https://github.com/CopperFr/VxKex/releases) · [应用兼容清单](https://github.com/CopperFr/VxKex/wiki/Application-Compatibility-List)

## 继续与停止条件

1. **先过 RT01。** 从一次干净启动和一次重启后复跑取得同一组版本信息和机器可读结果。失败时记录首次出错的 EXE 或进程、原生状态码和有关导入，不以窗口出现判定成功。
2. **再测运行时关键路径。** RT02 验证 CLI 使用的 Node 与 SQLite、子进程生命周期，RT03 验证多 View，RT04 验证真实 Renderer 沙箱、上下文隔离及 IPC 拒绝越权，RT06 验证隐藏窗口打印和真实 Office→PNG。首轮原有探针覆盖版本、SQLite、五个 View、隔离 IPC 与 PDF 文件头。使用 [Office 渲染基线](evidence/render-baseline-windows-x64.json) 补充 DOCX/XLSX/PPTX 输出和清理证据。
3. **用证据结束路线评估。** 建议为第一轮运行时预研留出 3–5 个工程日，从客体副本与候选介质就绪时开始计。若仍卡在 RT01，记录具体缺失接口和进程，按 W05 评估其是否适合有限的源码适配。若关键缺失涉及进程隔离、图形核心或广泛的系统语义，则单独评估现代 Electron 源码移植成本及持续更新能力。存在沙箱或数据完整性缺陷时，停止进入桌面发布流程。诊断用 PE 副本仅供定位。
4. **桌面候选进入集成前跑完整门禁。** 候选通过关键路径后，补齐 RT01–RT09。若兼容层通过，按固定版本和配置集成。若有限适配也无法满足隔离与渲染要求，暂停本地桌面交付，按原方案评估独立 CLI 或服务端路径。C 组先在 VM 验证，再用代表性终端验证图形、中文输入、EMF 和断网部署。运行时决定记录到 W05，附成功与失败的对照证据。

| 1      | W01 与 W05，运行时对照 | 建立客体副本，执行目标补丁、兼容层和运行时关键路径。复用 Docker 环境及客体探针。 [Docker 验证环境](docker-lab.md) · [探针](runtime-test.md)                                                                                                                                                                                                              |
| 1      | W03，Rust 原生组件     | 先用当前锁文件为较小的剪贴板辅助程序验证固定 Rust nightly、MSVC SDK 和 `x86_64-win7-windows-msvc` 的 `build-std`，再构建 XLSX Sidecar。提交工具链版本、命令、二进制哈希和 PE 导入结果。在客体验证支持的接口和最小 XLSX 样本，最终在目标机验证 EMF 剪贴板。 [Rust Win7 目标说明](https://doc.rust-lang.org/rustc/platform-support/win7-windows-msvc.html) |

| 2      | W04，CLI/MCP 契约      | 在现代 Windows 冻结命令、退出码、工具清单和已知差异。Win7 先验证随 Electron 分发的 `RunAsNode` 路径。需要独立 CLI 时，再单独评估满足实际依赖的 Node 版本及依赖 Shell 的命令范围。 [CLI 启动器](../../packages/cli/bin/genoffice.cmd)                                                                                                                     |
| 3      | W06，集成与交付        | 运行时路线确定后，接入 W02/W03/W04 候选。保留 A 组原版对照，先过 B 组的裁剪和回归，再输出 C 组离线安装及验收证据。 [验收矩阵](acceptance.md)                                                                                                                                                                                                             |
